# 4-апта: uniform + delta time

Үшбұрыштар шеңбер бойымен қозғалады (`uOffset`), өлшемі пульсациялайды (`uScale`),
қозғалыс кадр жиілігінен тәуелсіз (`angle += speed * dt`).

## Басқару

| Перне | Әрекет |
|-------|--------|
| W / S | айналу жылдамдығын арттыру / азайту (0.1 … 10.0 радиан/сек) |
| Q / E | орбита радиусын азайту / арттыру |
| R     | бәрін бастапқы күйге қайтару |
| F     | wireframe (бұрын W болған, енді W жылдамдыққа берілді) |
| 1 / 2 | GL_TRIANGLES / GL_LINE_LOOP |
| Space | ақ фон |
| Esc   | шығу |

## 1-тапсырма: dt-ны алып тастау тәжірибесі

> TODO (өзің толтыр, өз тәжірибеңе қарап): `angle += 0.02f;` + `glfwSwapInterval(0)` кезінде
> менде қалай жүрді, көршімде қалай жүрді.

Неге олай болады: `angle += 0.02f` — бұл «кадрға 0.02 радиан». Кадр жиілігі жоғары
компьютерде (мысалы 1000 FPS) үшбұрыш секундына 20 радиан айналады, ал әлсіз
компьютерде (мысалы 60 FPS) тек 1.2 радиан/сек — яғни бірдей кодта жылдамдық
әр машинада әртүрлі. `angle += speed * dt` болғанда қозғалыс уақытқа байланысты,
FPS-ке емес, сондықтан барлық компьютерде бірдей. Қазір `dt` қайтарылған.

## Қорғауға жауаптар

- **`speed = 1.5f` — кадрға ма, секундына ма?** Секундына: бірлігі радиан/секунд.
  Кадрға шаққандағы өзгеріс `speed * dt`, ал `dt` — алдыңғы кадрдан бергі секунд.
- **Неге W/S жеделдетуінде де `dt` керек?** `speed += 2.0f * dt` — жылдамдықтың өзгеру
  жылдамдығы да «секундына 2.0» болуы керек. `speed += 2.0f` деп жазса, перне басылған
  әр кадрда 2.0 қосылады және FPS-ке тәуелді болады — бұл сол қатенің екінші деңгейі.
